# v0.8.0 — Context-aware SCTP message I/O and bounded setup

Release tracking and exact tag/module verification: [#31](https://github.com/skill215/sctp/issues/31).
Implementation and review: [#30](https://github.com/skill215/sctp/pull/30).

## Features

- Add opt-in message I/O through SocketConfig.Messages, ReadEvent and
  WriteMsgContext. Preserve receive metadata, end-of-record flags, actual byte
  counts and partial/uncertain send evidence without replaying a short-write tail.
- Add typed parsing for association change, peer address change, send failure,
  shutdown and partial delivery notifications.
- Implement standard connection deadlines, context-aware resolution and dialing,
  cancellable AcceptSCTPContext and listener SetDeadline. Successful handoff
  detaches the returned object from the setup context.
- Add AddressLimits, SetupConfig, NewDialer and ListenContext for bounded
  local/remote address handling, owned configuration and a shared setup deadline.
- Add SetSocketTimeouts and BoundAddr, removing the need for adapter socket
  syscalls during setup. Timeout updates can partially succeed; imported listeners
  without a binding snapshot return ErrBoundAddrUnavailable.
- Add versioned MessageIORequirements and SetupRequirements queries. The bounded
  setup ledger is `bounded-setup-v2/linux/<GOARCH>`; use the query rather than
  copying upstream formulas or retaining the old 8192-byte assumption.
- Validate fragmented-message metadata and actual negotiated stream ranges.
  Restart invalidates the connection generation. Terminal receive failures after
  earlier fragments now require close and prevent further reads, including the
  zero-progress consume-error case discovered during review.

## Compatibility and limits

The minimum Go version remains 1.26. Production builds remain pure Go with
CGO_ENABLED=0. Linux with kernel SCTP remains the supported runtime, excluding
Linux/386; stub and cross-architecture checks do not add platform support.

SocketConfig gains the exported Messages field compared with v0.7.4. Migrate
unkeyed literals to keyed literals before upgrading. Nil Messages retains legacy
I/O; non-nil Messages selects an exclusive immutable message mode and rejects
conflicting callbacks and legacy/raw option mutation paths. Standard deadlines
now take effect on supported connections instead of returning unsupported errors.

Message mode uses one-to-one associations and fragmentation interleave level 0.
It validates required metadata, directional stream limits and message continuity;
it does not implement dynamic stream reset/expansion or application reassembly.
PPID 0 remains valid at the transport layer.

Resource figures are scoped logical charges, not RSS or total-allocation limits.
Caller buffers, adapter state, runtime/allocator costs, kernel queues and resolver
internals remain outside the documented ledger. Timeout changes are intended for
exclusive setup/takeover; callers close after a partial update failure.

This release does not implement the separate v1 rewrite, new one-to-many/peel-off
message support, automatic reconnect/replay or Diameter protocol policy.

## Validation and migration

The implementation candidate passed 14/14 CI jobs: Ubuntu 22.04/24.04 with
Go 1.26/1.27, ten race rounds per native job, checkptr, low-GC race, required
namespace tests, five million fuzz executions per native job, native Windows and
Linux/386 ownership checks, six QEMU ABI jobs and consumer/README checks.
Six wide-association-ID test executions were explicitly skipped on 32-bit
ARM/MIPS; QEMU results are ABI evidence, not native SCTP network evidence.

An independently downloaded exact candidate passed GOWORK=off/no-replace native
and race SCTP consumer runs. Publication is gated by a fresh full matrix on the final release commit.
The formal v0.8.0 module download, source identity and consumer verification
are recorded separately in #31; candidate checksums must not be reused.

diameterkit can then replace accept polling, setup socket syscalls, duplicated
address algorithms, upstream resource constants and SCTP metadata checks with
these APIs. Diameter framing, deadlines/policy, peer state and business budgets
remain downstream and require a separate migration and batch 64/65 acceptance.
