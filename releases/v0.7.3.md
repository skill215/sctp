Example client respects negotiated SCTP streams

The command-line example now selects its stream within the association's
negotiated outbound stream count while keeping PPID independent. Previously,
connecting to a peer allowing one or two streams caused the next send to use an
invalid stream, return EINVAL and terminate the client.

- Query the negotiated outbound stream count after connecting and cycle stream
  IDs within that range. PPIDs continue increasing independently.
- Add real subprocess regressions with one-stream and two-stream SCTP peers,
  checking four successive messages, PPIDs and stream IDs.
- Clarify the Linux-only platform policy and the library's scope and release
  boundaries. Keep application and adapter acceptance outside library gates.

Public library APIs, dependencies and socket behavior are unchanged. Go 1.26
remains the minimum. Standard deadlines and DialContext remain separate feature
work. Existing non-Linux compatibility checks do not extend platform support.

Publication requires the existing Go 1.26/1.27 native Linux matrix, ten
independent race/shuffle processes per kernel/toolchain, vet, strict checkptr,
low-GOGC, fuzz, required namespace regressions, README checks and architecture
ABI validation. The new subprocess regressions run as part of the full suite.
