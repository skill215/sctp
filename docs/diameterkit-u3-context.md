# Context resolution and connection handoff (diameterkit batch 59)

2026-11-09. Incremental change on v0.7.4/62ad388 plus the batch58 waiting foundation. This is not the separate v1 rewrite. It adds `ResolveSCTPAddrContext` and `(*SocketConfig).DialContext`; legacy resolve/dial/listen entrypoints and their Control behavior are unchanged.

Pass the same context to both calls for one total budget. The resolver uses `net.Resolver{PreferGo:true}` and the existing slash-separated-host/last-port grammar, IPv6 zone and service-port conventions. It selects one suitable address per explicit host (IPv4 preferred for `sctp`), deep-copies IP bytes, and never turns all DNS answers into an implicit multihoming group. Empty/single wildcard addresses retain legacy meaning. Cancellation is checked before and after lookup and between explicit hosts; DNS cancellation is exercised through a controlled Go resolver, not a public DNS dependency.

DialContext takes already-resolved addresses, validates and copies them and the configuration, and rejects a nil context/config or any Control callback with ErrInvalidConfig before creating a descriptor. A previously cancelled/expired context retains its cancellation cause. It creates one nonblocking close-on-exec socket, checks required setup, optionally binds, and invokes CONNECTX once. EINPROGRESS/EINTR/EALREADY/EISCONN enter the existing context-aware write poll gate rather than starting another association. SO_ERROR and Getpeername must confirm success; real setup/connect errors such as ECONNREFUSED retain errno identity.

The dial owns all new resources until the final publication check. Every failed path closes its owner. After poll completion, its temporary deadline/cancellation hook is retired, the socket owner is checked, and ctx is checked at the publication point. Cancellation observed there yields nil/error; cancellation after successful publication cannot close or impose a deadline on the returned connection. Context deadlines do not become post-dial read/write deadlines. Callers may set those explicitly.

New DialContext still creates a legacy-mode connection: NotificationHandler remains a copied synchronous receive callback, not a setup callback. No message mode or ReadEvent/WriteMsgContext is introduced here. Configuration/address values must not be concurrently modified during the call. DNS resolver infrastructure belongs to Go's net package; this change does not launch an unbounded per-dial background worker or promise cancellation of arbitrary user Control code.

Nine new tests cover grammar/family/port/zone and ownership, blocked DNS cancellation/shared budget, real SCTP success/post-publication cancellation, pre-fd Control rejection, repeated real ECONNREFUSED and fd accounting, pending-wait cancellation, the final publication gate and simultaneous accept/cancel. Pending wait and publication helpers isolate specific interleavings; they are not network-loss evidence. An external-package resolve Example executes; an external-package dial Example compiles but is not run against an assumed service. Full native/race/pure-Go/cross-compile evidence is recorded in diameterkit batch59.

Still open: U2 immutable message mode/peek-consume/checked receive facts/context writes, U4 notification/options/readback, complete exact-candidate U5 publication and native ABI/platform gates, and diameterkit's SCTP adapter/resource/Peer/deployment acceptance. No commit/tag/release or dependency lock is implied.
