# Explicit message I/O (diameterkit batch 60)

Incremental candidate on v0.7.4/62ad388 + batches58/59; not the separate v1 rewrite. `SocketConfig.Messages` is copied before socket creation. Nil keeps the legacy API. Non-nil requires explicit SNDRCV, level0 fragmentation interleave and only association/address/old-send-failure/shutdown/partial-delivery event bits. DATA_IO is derived. Message mode rejects Control and NotificationHandler before fd creation. Accepted connections inherit the listener's immutable copy. Keyed SocketConfig literals are recommended: the new field changes unkeyed literals.

The required EVENTS, NODELAY, FRAGMENT_INTERLEAVE and DISABLE_FRAGMENTS options are checked before connect/listen and verified again before publishing a connected/accepted descriptor. A mismatch fails closed. GetMessageOptions reads actual kernel values; it is not a cached declaration. InitMsg remains the existing option. No listener SCTP_STATUS is invented. Typed notification parsing remains the next U4 slice.

ReadEvent(ctx,data,notification,oob) requires distinct, sufficiently large caller buffers. MessageIORequirements is a pure ABI-layout query, not a kernel capability probe. It reports the minimum OOB and fixed notification prefix sizes and a conservative logical workspace bound derived from Go/ABI structures plus scalar workspace. It excludes caller buffers, Go call frames/heap overhead/errors/closures and all connection/poller/config/context hook/timer state. Full adapter memory accounting remains a separate gate; this is not a total allocation ceiling or a zero-allocation claim.

The read-direction gate covers an eight-byte peek and the consuming recvmsg. Notifications go to the notification buffer, data to data, ancillary bytes to OOB. No notification callback, full-payload allocation or silent notification loop occurs. ReadResult contains values only. Data can be fragmented; MSG_EOR defines completion, and InfoPresent distinguishes absent metadata from valid PPID0/Stream0. Unknown valid CMSG entries are skipped without dynamic parsing storage. EOF is distinct from a consumed zero-length EOR message.

An oversized notification returns RequiredNotificationBytes without consumption, bytes or peek flags; retrying with a larger caller buffer is permitted. A fixed-budget Diameter adapter may instead close. Actual TRUNC/CTRUNC, invalid/duplicate SNDRCV, notification size/EOR/kind mismatch or consumed-error returns preserve actual bytes/flags, set CloseRequired and latch reads unusable. No later read consumes the next frame. The caller must close; write mode does not promise recovery of the read boundary. Well-formed unknown raw notification types remain available for U4 classification. Raw fd access through SyscallConn is outside these guarantees.

WriteMsgContext sends one message with an explicit SNDRCV control block: TTL0, flags0 or UNORDERED and assoc0 or this connection's association. Empty data and other flags/IDs are rejected. A positive short success becomes io.ErrShortWrite; positive bytes plus a syscall error keep both facts. There is no tail retry. Per-operation context, mutable standard deadlines, socket timeout and Close use the existing direction gate and hook-retirement implementation. Cancellation is rechecked after peek; a completed consuming syscall retains its actual evidence.

Read/Write/SCTPRead/SCTPWrite, legacy wrapped I/O, SubscribeEvents, SetDefaultSentParam, public raw Setsockopt and PeelOff reject message mode. New message methods reject legacy mode. This does not change legacy callback/stream behavior. Required mode options are not mutable through the checked API; buffer and ordinary deadline setters remain usable.

Native loopback tests cover establishment notifications, fragmented messages, metadata0/46 and stream0/1, config copying/accept readback, pre-I/O rejection, cancellation/deadline update/Close and post-cancel reuse. Per-call internal fault injection covers oversize retry without consumption, malformed metadata and notification boundaries, latched reads, cancellation between peek and consume, partial writes and errors. It is not evidence that all five notification families were generated on the wire. U4 must add typed parsing and native long/failure/address/partial notification evidence, U5 exact installable candidate/platform acceptance, then diameterkit adapter/Peer/budget and DRA deployment validation. No release, dependency pin or persistence is introduced.
