# Typed Linux notifications (diameterkit batch 61)

Incremental candidate on v0.7.4/62ad388 plus batches58–60, separate from the v1 rewrite. ParseNotification is a pure decoder for the selected Linux SNDRCV/EVENTS/old-SEND_FAILED layout. It takes the complete bytes returned by ReadEvent and returns Notification, with a Kind discriminant, owned fixed values and an explicitly borrowed Tail. No persistence, peer state, retry or Diameter policy is involved.

Header.Length must equal the supplied length; reserved non-notification type values are rejected. Association changes require at least20 bytes and borrow their trailing info. Old send failures require at least48 bytes and borrow the returned payload, which may be only a fragment of the original message. Address changes require exactly148 bytes, shutdown12 and partial-delivery24. The selected partial layout includes stream and sequence fields, so their separate Presence values are true even when both numeric values are zero. Short16/20-byte prefixes are rejected, not guessed into a different ABI. Adding another layout requires a separate declared contract.

Unknown well-formed notification types, including the newer SEND_FAILED_EVENT, keep their original header and borrowed body. Unknown state/error/flags values in known notifications remain numeric; the parser does not invent a successful state or delivery conclusion. Address fields are decoded by checked AF_INET/AF_INET6 offsets into a netip.Addr value, with family, port, IPv6 flowinfo and numeric scope retained. There is no unsafe sockaddr projection, DNS or scope-name lookup. All SNDRCV fields are retained; PPID is converted from network order exactly once using the same decoder as ReadEvent.

Tail has capacity equal to length; zero-length tails are nil. It is not an owned copy and must be copied within the caller's budget before the input buffer is reused if retention is needed. Fixed fields stay valid after buffer reuse. Parsing does not allocate proportional to input size. A 1MiB borrowed-tail test verifies zero heap allocations for that selected path; this is not a total connection-memory claim. Notification result/parse workspace remains part of the future adapter's full memory accounting, separate from MessageIORequirements' receive/send workspace.

Malformed input returns a zero Notification and ErrMessageBoundary, with no partially trusted facts. ParseNotification is independent of SCTPConn and cannot change its read latch: after a consumed notification fails parsing, the Diameter adapter must close the connection. No parser error authorizes another read or reinterpretation as a different notification format.

Native Linux tests generate all five families using private loopback sockets: establishment and orderly shutdown; a queued reliable message followed by peer abort (old SEND_FAILED, larger than20 bytes); explicit selection of the existing primary path (ADDR_MADE_PRIM,148 bytes); and an abort after partial delivery begins (24 bytes). A real large notification is first refused without consumption using48 bytes and then read with the exactly reported size. Test-only raw controls configure buffers/partial-delivery threshold or abort a socket; no unstable send flags or mode mutation were added to the public API. These are local kernel tests, not DRA interoperability, real route loss or exhaustive state transitions.

Required option readback mismatches cover events/receive-info, NODELAY, interleave and fragmentation. A real UDP descriptor and invalid descriptor verify ENOPROTOOPT/EOPNOTSUPP and EBADF causes rather than fake success. Twenty accepted descriptors inheriting a deliberately corrupted NODELAY value are rejected and closed without fd growth, after which the same listener accepts and transfers data normally. Native tests run20 times under race detection. This is not kernel fault injection at every setsockopt/getsockopt call or every platform/ABI.

Five layout tests include unknown states, signed fields, IPv4/IPv6 scopes, full SNDRCV/byte order, owned fields and borrowed tails. All shortened fixed structures, oversized declared lengths, unsupported families, trailing bytes in fixed layouts and unknown/new event handling have deterministic tests. Fuzzing checks arbitrary bytes for panic-free, non-mutating, bounded results. Full test/race/CGO0 build and exact-source evidence are recorded by diameterkit batch61; no release or dependency pin is implied.

Sources: [Linux v6.12 UAPI](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/sctp.h), [Linux notification construction](https://github.com/torvalds/linux/blob/v6.12/net/sctp/ulpevent.c), [Linux socket implementation](https://github.com/torvalds/linux/blob/v6.12/net/sctp/socket.c), [RFC6458 notification semantics](https://www.rfc-editor.org/rfc/rfc6458.html#section-6.1). The ABI layouts are normative for this candidate; observations are tied to the tested kernel/architecture.
