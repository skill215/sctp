# Mutable deadline foundation (diameterkit batch 58)

2026-11-09. Base: v0.7.4 commit `62ad388be958f0bd19d29d63dfc05743726779a1`, also verified as origin HEAD. This is an incremental v0 waiting-layer change, not implementation or approval of the separate, uncommitted `redesign-sctp-v1` proposal.

On supported Linux targets, SCTPConn and its wrapped connection now implement SetDeadline/SetReadDeadline/SetWriteDeadline. Public deadlines persist until explicitly changed; zero clears them. SetDeadline commits both directions under one state lock, and setters wake queued operations as well as active poll waits. A failed underlying installation terminates I/O and retains the cause; no half-installed live connection is reported as success. Unsupported targets retain EOPNOTSUPP.

Each operation retains its original SO_*TIMEO deadline, including queue time. Clearing/extending public D cannot reset S. Standard deadline errors match os.ErrDeadlineExceeded; legacy S expiration continues to return EAGAIN. The internal context-aware waiting primitive additionally distinguishes ErrSocketTimeout while preserving EAGAIN, context.Canceled/DeadlineExceeded and net.ErrClosed.

The waiting primitive has one read owner and one write owner. It observes deadline broadcasts, uses per-waiter timers rather than a background queue, and registers an owner-checked cancellation callback only for the current owner. Cleanup stops or joins that callback before handing off the direction, restores current public D, and never blindly clears another operation's deadline. It does not close the connection merely because one operation is cancelled. Close wins at uncommitted entry, then context, then the earliest D/S (D wins equality). A committed nonblocking callback result remains authoritative even if cancellation or Close follows. EINTR in legacy send/receive returns to the controlled poll boundary instead of spinning in the callback.

Nine new TestMutableDeadline groups cover real SCTP read/write and both-direction reset, queued cancellation/deadline/Close, shortened deadlines, extend/clear before timeout commitment, successor isolation, fixed S, error precedence, admitted-result races and deadline-install failure. Barrier callbacks model narrowly identified interleavings; they are not packet-delivery evidence. Whole-library SCTP tests, pure-Go build/vet, and full race are recorded in the diameterkit batch58 evidence ledger. Linux arm64 and Windows amd64 are compile checks only, not native SCTP evidence.

Not delivered here: public Context message I/O, ResolveSCTPAddrContext/DialContext and their publication race, immutable message mode, peek/consume notification split, checked new metadata/truncation results, notification parser, options/readback/accept verification, or a Diameter adapter. Existing notification handlers remain synchronous user code and cannot be forcibly interrupted by I/O deadlines. Native architecture/ABI and complete exact-candidate publication gates remain open. No release/tag or dependency update is implied.
